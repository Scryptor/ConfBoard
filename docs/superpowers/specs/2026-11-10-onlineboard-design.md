# OnlineBoard — совместная доска в локальной сети

## Зачем
Несколько планшетов в одной Wi‑Fi сети рисуют на общей доске «как маркером», телевизор показывает ту же доску во весь экран. Без отдельного сервера, без ручного ввода адресов. Изменения видны у всех **во время** рисования, а не после.

## Решения пользователя
- Один APK на все Android‑устройства (планшет, телефон, Android TV).
- Нет общего сервера: первый запустивший становится хозяином, остальные сами к нему подключаются.
- ТВ — полноэкранный показ.
- Инструменты: маркер пальцем, базовые примитивы, текст, выбор цвета, стирание, отмена, масштаб двумя пальцами.
- Онлайн‑синхронизация в процессе действия.
- Доска сохраняется в памяти хозяина сессии.

## Решения, принятые мной (можно оспорить)
- Kotlin + Jetpack Compose, minSdk 24, один модуль приложения + чистый Kotlin‑модуль `core` (модель, протокол, сеть) — его можно тестировать на JVM и запускать «симулятор клиента» с компьютера.
- Обнаружение — UDP broadcast‑маяк хозяина (порт 45454) раз в секунду; данные — TCP (звезда через хозяина), бинарные кадры, TCP_NODELAY.
- У каждого устройства полная копия доски. При уходе хозяина новым становится следующий по порядку подключения участник; остальные переподключаются к нему по маяку. При подключении клиент отправляет свою копию, хозяин объединяет (union) элементы той же доски с учётом удалённых (tombstones).
- Если случайно оказалось два хозяина — побеждает более «старый» (раньше стал хозяином, при равенстве — меньший deviceId), второй становится клиентом.
- Сохраняет только текущий хозяин (автосохранение с задержкой ~1.5 с); после миграции сохранять начинает новый хозяин. Список досок, «новая доска», открыть/удалить доступны с любого планшета через запросы к хозяину.
- Ластик удаляет штрих/фигуру целиком при касании.
- Отмена/повтор — только своих действий (стек на устройстве).
- Масштаб и сдвиг у каждого устройства свои. ТВ автоматически вписывает всё содержимое в экран.
- ТВ: без панели инструментов, рисовать нельзя, маленький статус в углу.
- Живая синхронизация: штрих — UPSERT в начале, APPEND точек каждый кадр, финальный UPSERT в конце; фигуры и текст — UPSERT на каждое изменение.

## Не входит в первую версию
Выделение и перемещение, вставка картинок, экспорт в PNG, произвольный выбор цвета, работа через интернет, шифрование.

## Протокол
Кадр: `int длина | byte тип | payload`.
HELLO(deviceId, name, isTv, board) · WELCOME(board, members) · OP(sender, op) · MEMBERS · PING · BOARD_LOAD(board) · REQ_NEW_BOARD · REQ_OPEN_BOARD(id) · REQ_LIST_BOARDS · BOARD_LIST · REQ_DELETE_BOARD(id).
Операции: UPSERT(element) · APPEND(id, points) · REMOVE(ids).
Элементы: Stroke(points) · Shape(line/arrow/rect/ellipse, x1,y1,x2,y2) · Text(x, y, text, size); у всех id, цвет, толщина.
